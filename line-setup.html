1-1. LINE Developers Console を開く

🔗 LINE Developers Console を開く
サイトを間違えやすい注意: 開く先は developers.line.biz（開発者向け）です。 manager.line.biz（LINE Official Account Manager）は別サイトで、ここではProvider/Channelの設定はできません。URLバーを必ず確認してください。
LINEアカウントでログイン（iPhoneのLINEと同じアカウント）。初回はSMS認証が来ます。
すでにLINE公式アカウント（@xxxxxxx）を作成済みの場合: Providerは自動で作られているケースが多いです。Developers Console を開いた時点で左に Provider 一覧が出ていれば、Phase 1-2 はスキップして 1-3 の「既存のProviderをクリック」 → 中にあるMessaging API channelを開く → Phase 2へ進むでOK。

1-2. Provider を作成

  1. 「Create」または「新規プロバイダー作成」をクリック
  2. Provider名を入力（個人名でOK・後から変更可・外部に出ない）
  3. 「Create」を押下

1-3. Messaging API channel を作成

  1. 作ったProviderをクリック
  2. 「Create a Messaging API channel」をクリック
  3. 下表の通り入力
項目入力内容
Channel typeMessaging API（自動）
Provider1-2で作ったProvider名（自動）
Channel icon任意（空欄でOK）
Channel namehakushu-watch など
Channel description白州ウイスキー抽選通知
Category個人(個人事業主)
Subcategoryその他
Email自分のメールアドレス
利用規約全部チェック

「Create」を押すと作成完了。

チャネル一覧画面に hakushu-watch が表示されている
Phase 2 — 長期チャネルアクセストークン発行 所要 2分
123456
最重要の落とし穴: デフォルトで発行されるトークンは 短期（1ヶ月で失効）。長期トークンに切り替えないと1ヶ月後に通知が止まります。

2-1. Messaging API設定タブを開く

作ったチャネル画面の上部タブで「Messaging API設定」をクリック。

2-2. 長期トークン発行

  1. ページを下にスクロール
  2. 「チャネルアクセストークン（長期）」セクションを探す
  3. 「発行」ボタンを押下
  4. 表示された長い文字列を 今すぐコピー してメモファイルに保存
注意: この画面を閉じると再表示できません。コピーし忘れたら再発行が必要。

2-3. 自動応答を無効化

同じ画面の下部「応答設定」セクションで以下を OFF にする：

  • 応答メッセージ → OFF
  • あいさつメッセージ → OFF
これをやらないとbotがテンプレ応答を返してきて鬱陶しいうえ、Phase 4のWebhook検証が不安定になります。
200文字以上の長いトークンをメモファイルに保存済み

Phase 4 — User ID 取得 所要 10分・最難関
123456
注意: LINE Developers画面に表示される「Your user ID」はLIFF用で別物。実際の通知先IDは、bot にメッセージを送ってwebhook経由で取る必要があります。

4-1. ターミナル1: 受信スクリプトを起動

VS Code で Cmd+J でターミナルを開き、以下を実行：

cd hakushu-watch
.venv/bin/python -m tools.dump_user_id

出力例：

listening on http://0.0.0.0:8000 — point your LINE webhook here via ngrok
このターミナルは閉じない。次のステップ用に開きっぱなしにしておく。

4-2. ターミナル2: 公開URLを発行

VS Code 右上の「+」でターミナルをもう1つ開く（または Cmd+Shift+P → Terminal: Create New Terminal）：

ssh -R 80:localhost:8000 nokey@localhost.run

初回のみ「continue connecting? (yes/no)」と聞かれるので yes。接続後こんな表示：

=============================================================================== Welcome to localhost.run! ... ** your connection id is xxxxxxxx... ** xxxxxxxx.lhr.life tunneled with tls termination, https://xxxxxxxx.lhr.life

この https://xxxxxxxx.lhr.life の URL をコピー。このターミナルも閉じない。

4-3. LINE Developers で Webhook URL を設定

ブラウザの「Messaging API設定」タブに戻って：

  1. 「Webhook URL」欄に https://xxxxxxxx.lhr.life/webhook を入力
    末尾の /webhook を必ず付ける
  2. 「更新」ボタン
  3. 「検証」ボタン → 「成功」と出ればOK
  4. 「Webhookの利用」を ON
「成功」が出ない場合:
  • ターミナル1のスクリプトが動いているか
  • ターミナル2のssh接続が切れていないか
  • URL末尾 /webhook 付け忘れていないか

4-4. iPhoneから bot にメッセージ送信

iPhoneのLINEで、Phase 3で追加したbotとのトーク画面を開き、何でもいいので1通送る（例: test）。

4-5. User ID をコピー

ターミナル1（受信スクリプト側）にこんな行が出る：

>>> LINE_USER_ID = U1234567890abcdef1234567890abcdef

Uで始まる33文字をコピーしてメモファイルに保存。

4-6. 後始末

  1. ターミナル1, 2を Ctrl+C で停止
  2. LINE Developers の「Webhookの利用」は OFF に戻してOK（botは送信しかしないため）
メモファイルに ① 長期トークン と ② U で始まる33文字 の両方が揃っている

5-1. リポジトリ作成

🔗 GitHub: 新規リポジトリ作成
  • Repository name: hakushu-watch
  • Visibility: Public（Actionsの無料枠のため必須）
  • README/.gitignore のチェックは 外す（既存ファイルがあるため）
  • 「Create repository」

5-2. ローカルから push

VS Code のターミナルで（<あなたのID>を自分のGitHubユーザー名に置換）：

cd hakushu-watch
git remote add origin https://github.com/<あなたのID>/hakushu-watch.git
git push -u origin main
push時にユーザー名・PAT（Personal Access Token）を求められる場合あり。 GitHubの Settings → Developer settings → Personal access tokens で repo 権限のトークンを発行して使用。

5-3. Secrets を登録

GitHubのリポジトリページで：

  1. 「Settings」タブ
  2. 左メニュー「Secrets and variables」 → 「Actions」
  3. 「New repository secret」ボタン
  4. 下表の2件を1つずつ追加（それぞれ「Add secret」で保存）
NameSecret欄に貼る値
LINE_CHANNEL_ACCESS_TOKENPhase 2-2 で取った長いトークン
LINE_USER_IDPhase 4-5 で取った U....
Secrets画面に上記2件が表示されている
Phase 6 — 動作確認 所要 1分

6-1. workflow を手動実行

GitHubリポジトリの「Actions」タブで：

  1. 左メニューから「poll」を選択
  2. 右側の「Run workflow」ボタン
  3. ブランチ main を選んで「Run workflow」
  4. 30秒〜1分待つと実行が始まる

6-2. 成功確認

  • ジョブが 緑色（✓） になればOK
  • ログを開いて notifications=15 failures=0 のような行を確認

6-3. iPhoneのLINEに通知が来る

初回は登録対象15件分の通知が一気に届きます（更新検知メッセージとして）。 届けば セットアップ完了です。

以降、15分毎にcronが自動で回り、新しい抽選告知が出るとLINEへPush通知が届きます。

⚠️ トラブルシューティング

症状原因と対処
Phase 4の「検証」で失敗 ssh接続が切れている → ターミナル2を再接続→新しいURLでLINE側更新
User IDが >>> で表示されない 「Webhookの利用」がOFF / 「応答メッセージ」がON / URL末尾/webhook忘れ
GitHub Actionsで LINE push failed: 401 TokenがTYPO / 短期トークンを使った（1ヶ月超でexpired） → 長期トークンを再発行してSecret更新
GitHub Actionsで LINE push failed: 400 Invalid user User IDのコピペミス（必ずUで始まる33文字）
workflow が走るのに通知が来ない 「自動応答メッセージ」がONだとPushが詰まることあり → OFFに戻す
git push で「support for password authentication was removed」 パスワードでなくPATが必要。Settings → Developer settings → Personal access tokens で発行
ssh -R 接続が頻繁に切れる localhost.run のセッションは数時間で切れる仕様。User ID取得用の一時利用なのでOK
